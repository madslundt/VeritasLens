# Manual setup after `expo prebuild`

The Meta DAT SDK is not published to npm — it must be installed via Swift
Package Manager (iOS) and the Meta GitHub Packages Maven repo (Android).
After running `npx expo prebuild --no-install`, do the following:

## iOS — add the SDK via Swift Package Manager

The recommended path is to drive SPM from the Xcode UI, since CocoaPods'
SPM integration is fragile across Expo versions.

1. Open `packages/rayban/ios/<workspace>.xcworkspace` in Xcode.
2. **File → Add Package Dependencies…**
3. URL: `https://github.com/facebook/meta-wearables-dat-ios.git`
4. Version rule: **Up to Next Major** from `0.7.0`.
5. Add the products `MWDATCore` and `MWDATCamera` to the **app target**
   (NOT the ExpoMetaCamera pod target — Expo modules are linked indirectly
   via the host app).

The Swift code in `ios/ExpoMetaCameraModule.swift` already imports both
modules. After SPM resolves them, the module compiles.

## iOS — configure Info.plist

The DAT SDK needs additional Info.plist keys beyond what `app.json` injects.
Add these inside `<dict>` in `packages/rayban/ios/<app>/Info.plist`:

```xml
<!-- URL scheme for Meta AI callback -->
<key>CFBundleURLTypes</key>
<array>
  <dict>
    <key>CFBundleTypeRole</key>
    <string>Editor</string>
    <key>CFBundleURLName</key>
    <string>$(PRODUCT_BUNDLE_IDENTIFIER)</string>
    <key>CFBundleURLSchemes</key>
    <array>
      <string>veritaslens</string>
    </array>
  </dict>
</array>

<!-- DAT SDK config -->
<key>MWDAT</key>
<dict>
  <key>AppLinkURLScheme</key>
  <string>veritaslens://</string>
  <key>MetaAppID</key>
  <string>0</string>
</dict>

<!-- External accessory protocol -->
<key>UISupportedExternalAccessoryProtocols</key>
<array>
  <string>com.meta.ar.wearable</string>
</array>

<!-- Allow lookup of the Meta AI companion app -->
<key>LSApplicationQueriesSchemes</key>
<array>
  <string>fb-viewapp</string>
</array>
```

Append `bluetooth-peripheral` and `external-accessory` to the existing
`UIBackgroundModes` array (alongside `audio`).

Set `MetaAppID` to `0` while developing in Meta AI's Developer Mode.
For App Store distribution, replace it with the assigned Meta App ID
issued by the Wearables Developer Center.

## iOS — handle URL callbacks

The host app must call `Wearables.shared.handleUrl(url)` when a callback
URL arrives from the Meta AI app. Expo handles deep links via the
`expo-linking` mechanism, so add this in `App.tsx`:

```tsx
import * as Linking from 'expo-linking';
import { useEffect } from 'react';

useEffect(() => {
  const sub = Linking.addEventListener('url', async ({ url }) => {
    // Bridge to native — see the WearablesURLBridge module on the dev machine
    // to be created (forwards the URL into Wearables.shared.handleUrl).
  });
  return () => sub.remove();
}, []);
```

A small native bridge module (`WearablesURLBridge`) is required to wire
this through; create it on the dev machine after the SDK is integrated.

## Android — add the GitHub Packages Maven repo

Edit `packages/rayban/android/build.gradle` (the project-level file, NOT
the app-level one) and add inside `allprojects { repositories { ... } }`:

```groovy
maven {
  url = uri("https://maven.pkg.github.com/facebook/meta-wearables-dat-android")
  credentials {
    username = System.getenv("GITHUB_USERNAME") ?: project.findProperty("gpr.user")?.toString()
    password = System.getenv("GITHUB_TOKEN") ?: project.findProperty("gpr.token")?.toString()
  }
}
```

`GITHUB_TOKEN` must be a personal access token with `read:packages`
scope. The Meta SDK is publicly readable but GitHub Packages always
requires authentication for downloads.

## Android — initialize SDK

The DAT SDK's `Wearables.initialize(context)` is called automatically by
the module's `OnCreate` block. No host-app changes needed for that step.

For the registration flow, the host app must launch
`Wearables.startRegistration(activity)` on a button press in the LLM
screen or a dedicated onboarding screen. This is a one-time per-install
flow that opens the Meta AI app for permission grant.

## Android — Activity Result contract

`Wearables.RequestPermissionContract()` needs to be registered on the
main Activity. Add to `MainActivity.kt` (generated by prebuild):

```kotlin
private val wearablesPermissionLauncher = registerForActivityResult(
  Wearables.RequestPermissionContract()
) { result ->
  // Result is delivered to the suspending request hook in WearablesViewModel
}
```

A small expo module (`expo-wearables-registration`) could encapsulate
this — recommended once the audio-only path is proven.
