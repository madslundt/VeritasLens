# Changelog

## 0.12.0 — 2026-06-09
- **Game mode polish round 3: Random save-prompt, per-game language, inline-expanding editor, delete confirmation, conversation-memory hint.** Six follow-ups based on real-session feedback. **(1)** After a Random game ends, a new HUD `game-save-prompt` page surfaces the LLM-chosen topic and offers two options — `← Back` (first, the safe default for an accidental tap) and `Save as game`. Saving pushes a fresh `GamePreset` carrying the chosen topic, format, and difficulty, then drops the wearer back at the games sub-picker; Back just goes back. New `dismissRandomSavePrompt` + `saveCurrentRandomAsPreset` runtime helpers and a `handleGameSavePromptEvent` lifecycle handler wire the list taps. Cap-already-reached / empty-topic / KV-write failures flash on the next games-picker render via the existing `errorMessage` slot. Double-tap on the prompt continues to cancel like every other game-* page. **(2)** `GamePreset` gains an optional `language?: LanguageCode | null` override; the runtime resolves `preset.language ?? settings().responseLanguage` so legacy presets without the field keep using the global. `normalizeGamePreset` coerces unknown / missing codes back to `null`. The Settings → Games editor adds a Language picker whose first option is "Use default language" (binds to `null`); the rest mirror the global LANGUAGES list. **(3)** The Games editor now expands INLINE inside the row being edited instead of always rendering below the list, so it's visually obvious which preset the form belongs to. The form JSX is extracted into a `renderGameEditor()` helper called from two sites — inline within the active `<li>` for the edit-existing path and once below the list only for the create-new path (`gameEditingId() === null`). New `.lens-row--editing` CSS makes the row a stretch-aligned flex column and a new `.game-row-head` wrapper keeps the preset-info + delete buttons in a horizontal row above the editor block. **(4)** Tapping the row that's currently being edited closes the editor (toggle) rather than redundantly re-seeding the form with its own values; tapping a different row still swaps the form to that preset. **(5)** Delete now requires a two-tap confirm matching the "Clear all history" pattern: first tap arms (4-second auto-cancel via the existing `armDelete` / `cancelDelete` flow that history uses), second tap on the explicit `Confirm` button finalizes; `Cancel` aborts. The destructive action is no longer a single misclick away. **(6)** Settings → Conversation memory → "Carry summaries across sessions" gets a 3-line helper hint visible whenever the parent "Remember earlier moments" toggle is on, so users can read what the option means BEFORE turning it on. The existing privacy warning stays attached to the on-state (`⚠ Past-session summaries are sent to your provider in every prompt.`).
- **Game mode polish round 2: partial sessions persist, history surfaces unanswered counts, Settings preset row reworked.** Three follow-ups on the first game-mode polish pass. **(1)** Partial sessions are now persisted on a mid-game double-tap exit (via `cancelGame`) as long as the wearer has resolved at least one question, instead of silently erasing the progress they already made. The existing `saveToHistory` preset flag still gates the write so users who opted out keep that behaviour. A pure-cancel during the loading page (no answers yet) still drops without a write — nothing meaningful to record. The buildGameResult path is reused as-is; null answers naturally count as wrong against `correctIndex` so the score reflects only what was actually answered. **(2)** The history list / detail summary for game entries now appends `· N unanswered` to the bottom line whenever the wearer skipped questions (typical after a partial-session persist), so a glance at the row tells them how much of the game they actually played vs. abandoned. The score middle line is unchanged (`score / total`) so streak comparisons across full + partial sessions still line up. **(3)** Settings → Lenses → Games preset row is reworked: the whole row is now the edit trigger (tap the preset's topic/format/difficulty info to open the editor — no more separate "Edit" link), Delete becomes a proper styled button rather than a link-button so the destructive action reads as such, the "+ New game" affordance is promoted to a primary button instead of a link-button so the create action matches the visual weight of save/delete, and the editor's "Reset" button is gone (creates / saves close the editor; switching to another preset re-loads the form so the explicit reset is redundant). New `.lens-info--clickable` CSS variant gives the row a subtle hover/focus background so the click affordance is discoverable without adding chrome.
- **Game mode polish: quiz options shuffled, 4-option layout fits, richer reveals, picker hints at sub-menu.** Four fixes on top of the existing Game mode now that real sessions have surfaced rough edges. **(1)** Quiz-MC correct answers were landing first ~70 %+ of the time because Gemini (and chat LLMs generally) bias `correctIndex` toward 0 — the wearer noticed within a session and the quiz became "tap-the-top." A new `shuffleQuizOptions(questions, rng?)` helper in `src/personas/game.ts` runs a Fisher-Yates over each question's `options[]`, then remaps `correctIndex` to the new home of the same answer text. Skipped for true-false (positional: idx 0 = True, idx 1 = False) and riddle (no options). Runtime calls it in `src/runtime/game.ts` right after `parseGameResponse` so the shuffle happens at session-start; the parser stays pure and deterministic for unit tests. The `rng` is injectable so four new test cases in `tests/personas-game.test.ts` pin the outcome (single-question reorder + correctIndex remap, true-false untouched, riddle untouched, and a 10-question regression sweep asserting every original answer text still lives at the new `correctIndex`). **(2)** The 4-option quiz HUD was clipping the bottom option against the progress bar: title at y=8 height=80, list at y=92 height=152, progress at y=252 — leaving 38 px per item which the LVGL row chrome couldn't actually fit. Title now y=4 height=60 and list y=68 height=176 (~44 px per item) so all four rows render comfortably without scroll. **(3)** Quiz / True-False / Riddle reveal prompts rewritten from "one-sentence ≤180/200 chars" to "2-4 sentence ≤340 chars with a concrete supporting fact (date, name, mechanism)" so each round actually teaches the wearer something instead of just confirming yes/no. Feedback page body clip raised 320 → 480 chars to absorb the longer text without truncation on long correct-answer + reveal pairs. **(4)** The HUD picker entry for Games now reads `Games ›` instead of `Games` — single-chevron suffix telegraphs that tapping opens the sub-picker rather than starting a session, matching the platform convention for "this leads elsewhere" without burning a separate UI element.
- **Games moves to the bottom of the HUD picker.** Games has been pinned at the top of the picker since it shipped, which meant every fresh lens tap landed on Games first and required a scroll-down to reach the actual lens the wearer wanted. Lens taps are the common case; Games is the occasional case. `buildPickerItemNames` in `src/runtime/hud.ts` now appends `PICKER_GAMES_LABEL` after the personas list, and `pickerEntryAtIndex` resolves indices `0..N-1` to personas and index `N` (where `N = getPickerPersonas().length`) to Games. Out-of-range indices now fall back to the first persona instead of Games — matches the "tap to pick a lens" mental model. No coupling in lifecycle (its only consumer reads the `kind` discriminator, not the raw index) and no test changes needed.
- **Auto mode: hands-free analysis triggered by voice activity.** Until now every analysis required a double-tap on the temple — fine for deliberate fact-checks, awkward when the wearer's hands are busy (driving, presenting, holding a coffee) and basically useless for "just keep analysing whatever I say." Settings → Auto mode adds an opt-in toggle that watches the live PCM stream for voice activity and fires `runAnalysis()` automatically: once the wearer has spoken continuously for at least `autoModeStartMs` (default 1.5 s) the watcher arms, and once the speech is then followed by `autoModeSilenceMs` (default 2.0 s) of trailing silence the analysis fires — same entry point and post-trigger UX as a double-tap, so provider routing, retries, the existing no-voice gate, history writes and HUD transitions all work unchanged. Mid-utterance pauses below the silence threshold reset the silence counter so a "spoke, brief pause, kept speaking, then stopped" sequence fires exactly once at the end, not at each pause. After a fire the state machine resets to idle so the next utterance must build up start + silence from scratch — the watcher re-arms continuously without queueing analyses. Both thresholds expose a 0.5–5.0 s slider (250 ms step) under the toggle in Settings; the toggle hides the sliders when off so the UI doesn't grow chrome the wearer didn't ask for. Implementation lives in a new `src/runtime/autoMode.ts` module owning a 200 ms polling loop + idle/armed state machine that reads only the new bytes since the previous tick (via the existing `PcmRingBuffer.linearPcmSince(offset)` cursor), computes a single int16 LE RMS over the chunk, and classifies it against the user's existing `voiceGateRmsFloor` threshold — same knob that already governs the post-trigger gate, so users have one sensitivity setting to tune rather than two. When the gate is set to `0` (off) the watcher falls back to the historical 200 floor so auto-mode still has SOME notion of silence to fire on. The module is intentionally analysis-agnostic: it takes a `trigger` callback rather than importing `runAnalysis`, sidestepping a circular import and keeping the state machine trivially unit-testable. Lifecycle wires the watcher in `enterActiveSession` after the mic opens, tears it down in `leaveActiveSession` + `stopHudRuntime` alongside the other module-scoped timers, and registers a `createEffect` that toggles the watcher live whenever the wearer flips the Settings switch — no session restart required. While the watcher is running and an analysis isn't in flight, an `AUTO` label replaces the resting `•` recording dot in the baseline HUD's corner status slot so the wearer can tell at a glance no tap is required; the spinner / retry / error paths still own the slot transiently during analysis and restore `AUTO` on return to `listening`. The discreet layout is unchanged because its raison d'être is no chrome. Six new tests in `tests/autoMode.test.ts` lock the state-machine behaviour by feeding synthetic high-amplitude / zero-amplitude PCM chunks into a real `PcmRingBuffer` and advancing fake timers tick-by-tick: under-threshold voice does not fire, single arm + silence cycle fires once, the user's "voice / brief pause / voice / trailing silence" scenario fires exactly once, two back-to-back cycles fire twice (re-arm), stopping mid-armed suppresses any later fire, and an in-flight analysis suppresses the fire AND requires a fresh arm cycle afterwards so the watcher can never retroactively fire on stale silence the moment the analysis completes.

## 0.11.3 — 2026-06-05
- **Auto now shows which lens it actually used.** Previously when the Auto classifier dispatched (say) the Fact Check lens, the HUD result page and the phone history row were indistinguishable from a manual Fact Check pick — there was no way for the wearer to learn which lens Auto chose for a given tap, so feedback loops about Auto's routing quality were impossible. The result-page first line on the glasses now prefixes the existing session tag with `Auto · <Lens> · ` (e.g. `Auto · Fact Check · 1/3 · The Earth is round.`) on every page of an Auto-selected entry, and the same prefix lands on the history-detail page when scrolling back through past Auto entries. On the phone, history rows that were Auto-dispatched now show a small `Auto → <Lens>` chip between the timestamp and the question in the collapsed list and surface `Auto → <Lens>` as the detail header on the expanded view — so the picker quality is visible at a glance without having to expand each row. Threading happens through a new `autoLensLabel` option on `computePagesForResult` in `src/runtime/hud.ts`; the three call sites (`recomputeSessionPages` + the two history-detail builders) pass `entry.lensName` only when `result.autoSelected === true`. The synthetic-entry path used by tests and menu-replay (`synthesizeEntryFromResult`) now populates `lensId` / `lensName` from a result-type → persona-id mapping that derives the name via `getPersona(id).name` at lookup time, so persona renames in `BUILTINS` can't desync from the chip. `prefixOverhead` in `computePagesForResult` reserves one line for the combined `Auto · <Lens> · X/Y` head rather than just the session tag, so a long lens name like "Devil's Advocate" or "Logical Fallacy" that wraps the first line can't push body content past the container clip. `.history-lens` max-width bumped from 7rem to 12rem so the longest built-in label ("Auto → Devil's Advocate", 23 chars) fits without ellipsis. Three new tests in `tests/hud.test.ts` lock the prefix shape (active page, history-detail page, and the negative case for manual-lens entries).
- **Sharper Auto classifier routing for direct factual questions.** Reproduced case: asking *"what's the distance to the moon?"* routed to **Key Questions** when **Trivia** was the obvious right pick (the distance is a settled fact). The classifier prompt in `src/personas/auto.ts` had three collision points pushing Gemini toward Key Questions for any "what's X?" phrasing: a soft Trivia description ("a question with a direct factual answer"), a Key Questions description that overlapped with "asking questions" ("important questions remain open, unaddressed, or unresolved"), and a disambiguation rule whose "no clear known answer" wording was being misread as "the question hasn't been answered yet in this conversation" rather than "the topic has no settled answer in general knowledge." All three rewritten: the Trivia description now leads with concrete examples ("how far is the moon?", "who wrote Hamlet?", "what year did WW2 end?") and the explicit shape `who/what/when/where/how-many style lookups`; Key Questions is now scoped to *gaps in the discussion* (`SURFACE questions the participants are NOT asking but should — not to answer a direct question the speaker just asked`); and the ambiguous rule is replaced by two clearer rules that put Trivia first whenever the speaker directly asks a settled-fact question and reserve Key Questions for discussion-style audio. Three new prompt-shape regression assertions in `tests/personas.test.ts` lock the new phrases (and forbid the old "no clear known answer" wording) so a future edit can't silently regress the routing back to the broken state.

## 0.11.0 — 2026-06-03
- **Two more chat providers: DeepSeek and Perplexity, with STT decoupled from the chat host.** Until now every OpenAI-compatible provider had to either expose `/audio/transcriptions` on the same host (OpenAI, Groq Whisper-then-chat) or accept inline `input_audio` on chat completions (OpenRouter). DeepSeek (`https://api.deepseek.com/v1`) and Perplexity (`https://api.perplexity.ai`) do neither — they're strong chat backends (DeepSeek's reasoner; Perplexity's web-grounded `sonar-*` family is especially useful for the fact-check lens) but have no audio surface. So `OPENAI_BASE_URLS` adds both hosts and a new `OPENAI_CHAT_ONLY_HOSTS` set declares the chat-only category. `callOpenAiLens` in `src/llm/openai.ts` gains `transcribeBaseUrl` + `transcribeApiKey` options that, when set, route `/audio/transcriptions` to a different whitelisted Whisper host (Groq Whisper by default, OpenAI Whisper as the alternative) while the chat call still goes to the chosen chat host. The facade in `src/llm/index.ts` resolves this via a `resolveStt()` helper that fails fast with a clear error if the STT host has no key. New `STT_HOSTS` const + `STT_MODELS_BY_HOST` table (Groq: `whisper-large-v3-turbo` / `whisper-large-v3` / `distil-whisper-large-v3-en`; OpenAI: `whisper-1` / `gpt-4o-transcribe` / `gpt-4o-mini-transcribe`); persisted as `veritaslens.sttHost` / `veritaslens.sttModel`. `app.json` whitelist + permission desc updated. Two new tests in `tests/openai.test.ts` assert that a DeepSeek chat call hits `api.groq.com/openai/v1/audio/transcriptions` (STT) followed by `api.deepseek.com/v1/chat/completions` (chat) with the *respective* host's `Authorization` header — no key spillover between hosts.
- **Settings UI: four-tab bottom navigation.** The single Settings tab had grown to fit Lenses, Provider + key + model, STT, Response language, Recording buffer, Voice gate, Voice trim, Discreet, Auto-summary, Meeting Prep, plus a History tab on top — too dense to scan and the Save button was easy to miss above the fold. The top `.tab-bar` is replaced with a fixed bottom `<nav class="bottom-nav">` carrying **Lenses · History · Settings · LLM** (sparkle `✦` icon — the de-facto AI iconography from Gemini / Apple Intelligence / Copilot). Each tab renders its own scope: device status badge moved to the top of Lenses; Lenses card with the Auto-lens enable list and Meeting Prep editor lives here too; History tab unchanged; Settings tab holds language / buffer / voice gate / voice trim / discreet / auto-summary; LLM tab holds provider / keys / models / transcription / STT. `.settings` bottom padding bumped to clear the nav + bar without leaving dead space.
- **One global Save, fixed above the bottom nav.** Replacing the in-form Save buttons that were buried below long forms. A single `.action-bar` renders inside `.bottom-stack` (a fixed container that also owns the bottom nav), so the bar sits flush against the nav with no gap and shares the same surface treatment — it reads as part of the navigation chrome, not a competing alert. Visible whenever any draft on any tab differs from the persisted store; carries "Unsaved changes" + a Save button that calls a single `onSave` persisting all drafts in one `Promise.all`. The LLM-side `canSave` gate (the `/models` probe that verifies a key before persisting) only disables Save when there are LLM drafts to write — plain language or buffer changes can save without re-validating an API key.
- **Per-tab dirty indicators.** Each bottom-nav button shows a small amber dot in the upper-right of its icon when its scope has unsaved drafts (Lenses dot covers Auto-lens toggles + Meeting Prep; Settings dot covers app preferences; LLM dot covers provider / key / model / STT; History never lights up — read-only). Dots disappear after a successful Save.
- **Auto-lens toggle and Meeting Prep editor now wait for Save instead of autosaving.** Previously the Auto-lens checkboxes wrote through to `saveAutoDisabledLenses` immediately on click, and the Meeting Prep editor autosaved on a 600 ms debounce. With the dot indicators, both now buffer changes locally (`draftAutoDisabledLenses` / `prepDraft`) and persist only when the global Save fires — matching the explicit-save model of the LLM and Settings tabs. The Meeting Prep editor's old inline "Saving…/Saved" badge is gone; byte-budget overruns still surface inline next to the meter so the user knows exactly what to shrink before saving. `lensDirty` normalizes both sides before comparing (drops fully-empty rows so the "always at least one row" seed on a fresh install doesn't read as a diff; compares by label+body, not id, since ids regenerate on add), and the post-save flow re-seeds `prepDraft` from the persisted store so label-trim normalization (slicing at `MEETING_PREP_LABEL_MAX`) can't leave the dot stuck on.
- **Auto-lens row is fully clickable, not just the checkbox.** The label now spans the row with `width: 100%` and padding-on-label, so a tap anywhere in a lens row toggles via the native label-to-input association. Previously the row's outer padding gutter was dead space.
- **API-key dashboard links for every provider.** The Gemini field has always linked to `aistudio.google.com`. Now each OpenAI-compatible host's key field links directly to its dashboard: `platform.openai.com/api-keys`, `console.groq.com/keys`, `openrouter.ai/keys`, `platform.deepseek.com/api_keys`, `perplexity.ai/settings/api`. Rendered via a new `<ApiKeyLink host>` component with one `<Match>` per host so the `href` URL literal sits on the same line as the `href=` attribute — required by the `network-whitelist` contract test, which excludes URLs that appear inside JSX navigation attributes (these open in the host browser, not the WebView, so they're correctly out of scope for the in-app whitelist).
- **STT API key input is rendered inline when needed.** When the chat host is DeepSeek or Perplexity, the Speech-to-text section now shows an editable API-key field for the picked STT host (Groq or OpenAI), pre-filled from the per-host `draftOpenaiKeys[draftSttHost()]` if a key has already been entered. No more "switch the Provider dropdown to Groq, enter the key, then come back" workflow — fill it inline. The hint clarifies the key is used for transcription only and links to that host's keys page via the same `<ApiKeyLink>` component.

## 0.10.0 — 2026-05-30
- **Tidier auto-summary HUD labels and a cheaper gate.** The picker badge baseline now reads `Summary on` (was the lowercased `summary`), the generating state reads `Generating…` (was `summarizing...`), and the ready flash reads `Summary ready!` (was `summary ready`) — same 180 px container width, no clipping risk on hardware. More importantly, no summary is generated when the session has been recording for under 1 minute or when the user hasn't asked a single question (no completed analyses in this session). A shared `canRunSummary()` helper in `src/runtime/lifecycle.ts` guards `runAutoSummary` (the 5-minute tick), `runStopTimeSummaries` (the exit-time last-tick + final synthesis), and `runMidSummary` (the menu item) so a brief picker visit with no taps can no longer burn a Gemini call. The "Mid-session summary" / "Refresh summary" menu rows are disabled when the gate is closed; tapping the disabled row flashes the specific reason (`Record ≥1 min first` or `Ask a question first`) in a new bottom hint footer on the menu page for 5 seconds, via a new `flashMenuHint` helper that mirrors the existing picker / active hint patterns.
- **Conversation memory: lenses can now recall what was said earlier in the session.** Until now the "Enable background summaries" setting only produced a final session summary written to History — nothing from the intermediate 5-minute ticks was ever fed back into subsequent lens calls, so questions like "what did they just say about X?" had no way to resolve. With the setting on, `buildPromptWithContext` and `buildMeetingPromptWithContext` now prepend a `CONVERSATION CONTEXT` block to every lens call containing the last 2 intermediate summaries (~10 minutes of conversation), hard-capped at ~600 tokens (2400 chars, ~4 chars/token) with oldest-first trimming when over budget. The block is wrapped with an explicit grounding directive ("Base your answer on the JUST-spoken audio. Use this context ONLY to resolve references the speaker explicitly makes back to it. Do NOT extract new claims or facts from this context.") to keep fact / claim lenses from confabulating fresh extractions out of summarized history. The recall logic lives in a new pure helper `src/runtime/recallContext.ts` (constants + `buildRecallContextLines`) so unit tests can exercise the trim / cap / empty paths without dragging in the SDK + bridge mocks. The Settings checkbox is relabeled "Conversation memory" with help text that now describes recall behaviour first and the summary side-effect second; the 5-min request cadence warning stays. In-session only — nothing carries between sessions, and the existing `intermediateSummaries[]` accumulator is still cleared on `leaveActiveSession` / `stopHudRuntime`.
- **ERR corner glyph now self-clears.** When `callLens` exhausts retries, the top-right `ERR` glyph used to persist until the wearer figured out the right gesture to dismiss it (swipe-down past the last result page, menu → Back, or start a new analysis) — feedback said the recovery flow was unclear. The status now auto-demotes back to `listening` after 5 seconds via a new `errClearTimer` + `clearErrorState()` pair, and any incoming user gesture clears it immediately via an early call in `handleEvent`. The fall-through is deliberate: a double-tap during ERR both clears the glyph AND triggers a fresh analysis on the existing audio buffer (which was the prescribed recovery anyway). The timer is cancelled in both `leaveActiveSession` and `stopHudRuntime` so it can't fire into a torn-down HUD page. No new hint or label is added — the gesture vocabulary is unchanged, only the lingering visual is.
- **Tighter Gemini model dropdown filter.** The model picker pulls from Google's `/v1beta/models` and uses a regex blocklist on the names to strip non-chat variants (TTS, image, live-audio, embedding). The list was too permissive: `aqa` (retrieval-grounded QA — different request envelope), `learnlm` (strict responseSchema unreliable), `-vision` (no audio input), `-latest` aliases (always duplicates of an already-listed versioned id), and the retired `gemini-1.*` line all reached the dropdown and then 4xx'd at request time when the user picked them. `GEMINI_NON_CHAT_KEYWORDS` in `src/llm/gemini.ts` now rejects all five categories. The filter stays metadata-driven — no hardcoded allowlist — so new `gemini-2.x` / `gemini-3.x` families still appear automatically the next time Google publishes them. `tests/gemini.test.ts` extended with a focused case feeding one of each rejected category and asserting only the real 2.x+ ids survive.

## 0.9.1 — 2026-05-29
- **Continuous firmware scroll on the mid-session Summary HUD.** The Summary view used to paginate into 7-line pages with a `● ○ ○` dot indicator and flip pages on each swipe; a 0.9.1 interim step replaced page-flip with a 3-line stepped slide. Both still felt like discrete jumps. The Even Realities G2 display docs (https://hub.evenrealities.com/docs/guides/display) state that "if content overflows and the container has `isEventCapture: 1`, the firmware handles internal scrolling" — and the Summary's body container already had `isEventCapture: 1`. So `showMidSummaryPage` in `src/runtime/hud.ts` now hands the body container the full composed body string (title + summary + key points, capped at the SDK's 1000-char `rebuildPageContainer` limit on first show / 2000-char `textContainerUpgrade` limit on in-place refresh, with `…` truncation) and the firmware scrolls it natively on swipes. The app-side line-window scroller — `midSummaryLines`, `wrapTextToLines`, `getMidSummaryMaxScrollOffset`, `scrollMidSummaryToOffset`, `midSummaryScrollOffset`, `MID_SUMMARY_SCROLL_STEP`, the mid-summary branch in the SCROLL_TOP/BOTTOM dispatcher, and the dot indicator — is all deleted. Refreshes use `textContainerUpgrade` so the firmware scroll position survives a summary refresh instead of snapping to top. Single-tap still opens the menu; double-tap still triggers analysis. Scope is the mid-summary page only — `history-detail` and the active-page scrollers are unchanged (they're multi-claim / multi-entry, not single-overflow regions).
- **Tighter Gemini retry coverage on flaky upstream.** 429 / 503 / 504 errors from Gemini are real, but `callLens` was making the user-facing impact worse than necessary: 504 Gateway Timeout was never retried (it fell into the generic `!response.ok` branch and threw on the first occurrence), network-level `fetch` failures from a dropped phone connection were never caught (a single `TypeError` abandoned the whole call), and there was no per-attempt fetch timeout so a hung socket blocked until the WebView's default socket deadline (~120 s) instead of failing fast. `src/llm/gemini.ts` now retries 504 alongside 429/503, wraps `fetch` in a try/catch that retries any non-abort error, and combines `opts.signal` with a 30 s per-attempt deadline via a small `withFetchTimeout` helper so a single slow attempt fails fast and retries cleanly. Outer-signal aborts (double-tap cancel, teardown) still propagate immediately — only timeouts and network errors trigger a retry. Fallback retry delays (the 1 s / 5 s defaults used when Google doesn't supply a `retry-after` or `retryDelay` hint) now carry ±25 % jitter to de-correlate the Auto lens's parallel classifier + speculative retries; server-supplied hints stay exact. The 8 s `MAX_RETRY_DELAY_MS` cap is unchanged — quota errors with longer hints still fail fast rather than freezing the HUD for 30+ s. The `R1/3 R2/3 R3/3` spinner indicator picks up the new retry sources automatically.
- **Smoother analyzing spinner; no more stuck glyph in the top-right.** The corner spinner used to run on a fixed 180 ms `setInterval` that fired two SDK writes per tick (status + menu spinner) regardless of which slot was on screen — when the bridge stalled, queued ticks fired back-to-back and produced visible "freeze, then rush" jitter. The spinner now self-reschedules via `setTimeout` after each write resolves, and only writes to the currently visible slot (status on the active page, menu spinner on the menu), halving bridge throughput in steady state. `stopSpinner` also synchronously resets the canonical status / menu-spinner frame buffers before the async clear writes, so the follow-up `setLensResult → renderActivePage` rebuild can no longer bake a stale spinner glyph into the freshly built status container — fixes the spinner occasionally hanging in the top-right after a result lands.

## 0.9.0 — 2026-05-28

## 0.8.2 — 2026-05-26
- **Fix store-review rejection on the connection prewarm.** Boot-time `prewarmGeminiConnection()` now opens the TLS+HTTP/2 connection by GET-ing `/v1beta/models` instead of `/$discovery/rest`. The discovery endpoint returned a network-layer failure on bare cross-origin requests (no HTTP response), which the Even App store reviewer's network monitor flagged as a connectivity defect even though our code swallowed the error. `/v1beta/models` resolves to a real HTTP status (403 JSON without a key, 200 with one), so the warm-up no longer trips the check. No behavioral change for users.
- **Trim non-speech audio toggle.** Settings now exposes a checkbox for the previously hidden `voiceTrimEnabled` setting (default on). When on, the upload is cropped to detected speech segments via Silero VAD — smaller payload, less noise for the LLM. Turn off for ambient-audio analysis (music, scene, room tone). Has no effect when Silero is unavailable; the FFT fallback returns no segment list so the full buffer is sent unchanged.

The CONTEXT block now ends with an instruction telling the model to resolve "today", "tomorrow", "in N days", "until X", "how long ago was Z" etc. against the Date/Time fields and compute a direct answer instead of skipping the question.

The Settings error banner CSS also gained `overflow-wrap: anywhere`, `white-space: pre-wrap`, and a scrollable `max-height: 40dvh` so long messages wrap and scroll instead of getting visually clipped at the WebView edge.

Empty falls back to the static default (`whisper-1` / `whisper-large-v3`); type in `gpt-4o-mini-transcribe`, `whisper-large-v3-turbo`, etc. to override per host. Per-host storage means swapping providers keeps each side's customization. The Test-model probe uses the draft transcribe model end-to-end, so a bad override surfaces immediately. OpenRouter (inline-audio host, no STT endpoint) doesn't show the field.
- **Voice detection is now a sensitivity slider, not an on/off toggle.** Settings → Voice detection sensitivity exposes the RMS floor as a step-50 range (0–1000): `0` disables the gate entirely (every tap reaches the LLM), `200` keeps the historical default, lower values are more permissive (useful when quiet speech was being misclassified as `○` silence on low-amplitude mic captures), higher values gate out more background noise.
